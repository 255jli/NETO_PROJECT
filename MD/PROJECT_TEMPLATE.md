# PROJECT TEMPLATE — единый шаблон проекта
## Как его собрал бы Senior-инженер + эксперт по инвесторам

Этот шаблон — слияние двух взглядов на один проект:
- **Senior-инженер** отвечает за: архитектуру, MVP, этапы разработки, риски, метрики продукта, качество.
- **Эксперт по инвесторам** отвечает за: упаковку смысла, рынок, юнит-экономику, дорожную карту под гейты финансирования, ask и использование средств.

Ключевая идея: **каждый инженерный этап = инвесторский «гейт»**. Инвестор видит прогресс не «красивые слова», а работающий инкремент + измеримую метрику. Инженер видит не «абстрактную стратегию», а конкретный скоуп до следующего гейта.

Применяется на примере NETO (прототип уже есть в `neto_prototype/`), но структура универсальна и переиспользуема.

---

## 0. One-pager (упаковка для инвестора)
> Заполняется первым — это «крючок».

- **One-liner:** «NETO — ИИ-ассистент, который сам принимает звонки и чаты бизнеса 24/7 и превращает обращения в продажи».
- **Проблема:** 25–35% входящих звонков МСБ остаются без ответа; оператор стоит от 60 000 ₽/мес; существующие решения требуют разработчиков и недель внедрения.
- **Решение:** голосовой ИИ + чат-виджет + анализ рынка в одной среде; запуск за час, без программирования.
- **Модель:** pay-as-you-go (0,50 ₽/мин голос, 0,25 ₽/запрос), без абонентской платы.
- **Ask:** не деньги, а доступ к песочнице SpeechKit/GigaChat, облако, Demo Day.
- **Размер рынка:** TAM (РФ, 2025) $750 млн; SOM на 2027 ~25 млн ₽, 2029 ~140 млн ₽.

---

## 1. Проблема и ЦА
- Сегменты ЦА (из презентации): автосервисы, онлайн-школы, стоматологии + расширение «магазин цветов / склад».
- Для каждого сегмента: типовой сценарий, боль, метрика успеха («ни одного пропущенного обращения»).
- Правило эксперта: **один сегмент = один сценарий = одна метрика**, а не «продукт для всех».

---

## 2. Решение: продукт и модули
| Модуль | Что делает | Где в прототипе |
|---|---|---|
| Голосовой ассистент | Приём звонков, запись, заказ | `voice.html` |
| Чат-виджет | Обработка текстовых обращений | `widget.html` |
| Интеграции/знания | Как ИИ узнаёт о компании | `integration.html` |
| CRM | База клиентов | `crm.html` |
| Анализ рынка | Этичный парсинг цен конкурентов | `parsing.html` |

- Инженерный принцип: **каждый модуль — отдельная страница/вкладка**, UI единый (стиль «Обзор»), данные — демо-фронтенд, API подключается позже.

---

## 3. Бизнес-модель и юнит-экономика
- Источники выручки: голос (₽/мин), текст (₽/запрос), аналитика.
- Юнит-экономика: себестоимость минуты (0,50–0,70 коп. на сторонних API) → маржинальность ~85%.
- Точка безубыточности: ~250 клиентов; MRR-форкасты: 500 клиентов ≈ 400 тыс. ₽/мес, 2000 ≈ 1,3 млн ₽/мес.
- Формула для инвестора: **MRR = активные клиенты × ARPU × retention**.

---

## 4. Архитектура и стек
- Микросервисная архитектура, мульти-API-маршрутизация (Whisper/SpeechKit + GigaChat/NLP).
- Контекстная память, сценарии диалога, коннекторы к amoCRM/Битрикс24/1С.
- Соответствие 152-ФЗ: данные только на серверах в РФ.
- Прототип сейчас: Flask (Python) + Jinja-шаблоны + vanilla JS; стили `style_1/2/3.css`.
- Инженерный принцип: **сначала рабочий демо-фронтенд, потом тонкий API-слой**, не строить бэкенд до валидации UX.

---

## 5. Дорожная карта с инвесторскими гейтами
| Фаза | Инженерный скоуп | Инвесторский гейт | Метрика выхода |
|---|---|---|---|
| 0. Демо-прототип | Кликабельный UI всех вкладок | Представление на Demo Day | Сценарий звонка + заявки работает |
| 1. Пилот | Подключение реального номера, 1 сценарий | Закрытый тест 3–5 клиентов | N звонков/нед, % принятых |
| 2. Масштаб | Коннекторы CRM, аналитика, биллинг | Первые платящие клиенты | MRR > 0, churn < X% |
| 3. Рост | Мульти-канал, self-service | Привлечение инвестиций | GMV/MRR + retention |

Правило: **гейт открывается только при достижении метрики**, не по календарю.

---

## 6. Метрики (две панели — продукт и бизнес)
- Продукт (Senior): скорость ответа, % пропущенных = 0, длительность, точность распознавания, N ошибок сценария.
- Бизнес (инвестор): MRR, ARPU, CAC, LTV, churn, маржинальность, N активных клиентов.

---

## 7. Риски и митигация
| Риск | Тип | Митигация |
|---|---|---|
| Стоимость сторонних API на этапе отладки | Финансовый | Ask: тестовый доступ к песочнице |
| Низкая точность распознавания акцентов | Технический | Whisper + SpeechKit комбинация |
| Регуляторика 152-ФЗ | Юридический | Хранение только в РФ с первого дня |
| «Продукт для всех» | Стратегический | Один сегмент на фазу |

---

## 8. Ask и использование средств
- Не «сколько денег», а **что нужно для следующего гейта**: API-доступ, облако, менторы.
- Чёткий Use of Funds: таблица «ресурс → что получим → какая метрика подтвердит».

---

## 9. Команда и роли
- Senior-инженер: архитектура, MVP, качество, метрики продукта.
- Эксперт по инвесторам: упаковка, рынок, юнит-экономика, дорожная карта, питч.
- Правило: **оба смотрят один и тот же документ** — это и есть «шаблон проекта».

---

## Как использовать шаблон
1. Скопируйте структуру под свой проект.
2. Заполняйте разделы 0→9 сверху вниз.
3. Каждое обновление кода сопровождается обновлением раздела 5 и 6 (скоуп + метрика).
4. Инвестору показывайте разделы 0, 3, 5, 8; инженеру — 4, 6, 7.
