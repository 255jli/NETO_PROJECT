# Типовые пользовательские сценарии (User Journeys)

Документ описывает типовые пути пользователя: от первичной регистрации до получения результата. Каждый сценарий включает профиль пользователя, последовательность действий и ожидаемый результат.

## Сценарий 1: Минимальное внедрение (Текстовый канал)

- **Профиль:** самозанятый, продающий товары через сайт или соцсети. Бюджет ограничен.
- **Действия:**
  1. Регистрация в системе.
  2. Переход в раздел «Виджет».
  3. Настройка визуального оформления и сценария приветствия.
  4. Копирование кода для вставки на сайт.
- **Результат:** сайт получает автоматическую обработку текстовых обращений 24/7. Разделы «Телефония» и «CRM» остаются неактивными.

## Сценарий 2: Комплексная автоматизация (Телефония + CRM)

- **Профиль:** владелец малого бизнеса (например, перепродажа мебели), отсутствующий на точке в течение рабочего дня.
- **Действия:**
  1. Прохождение адаптивного руководства («Первые шаги»).
  2. Подключение виртуального номера в разделе «Телефония».
  3. Загрузка прайс-листа и прохождение опроса в разделе «Интеграции».
  4. Настройка переадресации и сценариев записи в разделе «Голос».
- **Результат:** система принимает звонки, квалифицирует клиентов, записывает их и создаёт карточки во встроенной CRM. Владелец получает сводку по выполненным заявкам.

## Сценарий 3: Аналитический (Мониторинг рынка)

- **Профиль:** бизнес, использующий платформу исключительно для конкурентной разведки.
- **Действия:**
  1. Переход в раздел «Парсинг».
  2. Добавление ссылок на сайты конкурентов и перечня товаров для мониторинга.
- **Результат:** система формирует отчёты по динамике цен и наличию ассортимента у конкурентов. Функции телефонии и чат-виджета не используются.

## Сценарий 4: Интеграция с внешней инфраструктурой

- **Профиль:** компания, уже использующая внешнюю CRM (amoCRM, Битрикс24).
- **Действия:**
  1. Переход в раздел «Интеграции».
  2. Выбор опции «У меня есть CRM».
  3. Ввод API-ключей или авторизация через коннектор.
- **Результат:** NETO выступает в роли шлюза: принимает обращения и транслирует их напрямую во внешнюю CRM пользователя. Встроенная CRM платформы не используется.

## Сценарий 5: Гибридный (Чат + Голос без CRM)

- **Профиль:** компания, которая хочет закрыть и текстовые, и голосовые обращения, но использует собственную учётную систему, отличную от стандартных CRM.
- **Действия:**
  1. Настройка чат-виджета в разделе «Виджет».
  2. Подключение виртуального номера в разделе «Телефония».
  3. Настройка собственной интеграции через API в разделе «Интеграции».
- **Результат:** платформа обрабатывает оба канала, а данные передаются во внешнюю учётную систему по API. Встроенная CRM остаётся выключенной.

## Сценарий 6: Контроль расходов (Счёт)

- **Профиль:** пользователь, который хочет держать расходы под контролем и понимать структуру затрат.
- **Действия:**
  1. Периодический переход в раздел «Счёт».
  2. Изучение детализации списаний по каналам.
  3. Анализ объёмов голосового трафика и текстовых запросов.
- **Результат:** пользователь получает прозрачную картину расходов и может скорректировать настройки (отключить номера, изменить сценарии), чтобы оптимизировать затраты.
